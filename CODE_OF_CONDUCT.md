# GoodQ4All Code of Conduct

## Purpose

GoodQ4All is a local-first engineering project built around careful reasoning,
clear evidence, and respectful collaboration. We want contributors, reviewers,
and users to feel safe participating without being talked down to, harassed, or
pressured into unsafe disclosure.

## Expected Behavior

Participants in this project are expected to:

- communicate respectfully and assume good intent
- keep disagreement focused on code, documentation, tests, and evidence
- give actionable technical feedback rather than personal criticism
- respect privacy, licensing, and security boundaries
- avoid posting secrets, private data, or copyrighted media excerpts
- help newcomers learn the project’s norms without ridicule

## Unacceptable Behavior

The following behaviors are not acceptable in project spaces or project-related
private communication:

- harassment, threats, stalking, or intimidation
- discriminatory or demeaning language directed at any person or group
- personal attacks, dogpiling, or deliberately hostile review behavior
- sexual language or unwanted sexual attention
- doxxing or sharing another person’s private information without permission
- retaliation against someone who raises a conduct or safety concern
- publishing sensitive security details irresponsibly before maintainers can assess them

## Scope

This code of conduct applies to:

- GitHub issues, pull requests, and discussions
- documentation reviews and project planning threads
- release and support conversations connected to the project
- project-related private outreach between participants

## Enforcement

Project maintainers may take any action they deem appropriate to protect the
health of the project and its participants, including:

- editing, hiding, or removing content
- closing discussions or pull requests
- rejecting contributions
- temporarily or permanently restricting participation

## Reporting

If you experience or witness unacceptable behavior, contact the maintainers
privately through GitHub rather than posting sensitive details publicly. Include
links, screenshots, or other concrete context when possible.

If the concern also involves a security issue, follow the reporting guidance in
[`SECURITY.md`](SECURITY.md).
