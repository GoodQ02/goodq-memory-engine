# TurboQuant Hybrid-Precision Vector Caching

This document details the mathematical framework, cache invalidation policies, and integration details of the **TurboQuant** sidecar vector caching system implemented in GoodQ4All.

---

## 1. Architectural Overview

GoodQ4All operates on a **hybrid-precision vector storage model**. While 32-bit floating point (`float32`) embeddings generated by perception models represent the authoritative system truth (stored in Qdrant and FAISS), they are heavy to load and scan continuously on lower-end local desktop hardware.

To accelerate top-K candidates pre-filtering and pruning without losing precision, TurboQuant stores quantized, compressed representations of these vectors directly in SQLite as "sidecar" columns.

```
       [ Authoritative Ingestion ]
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
   [ Qdrant/FAISS ]      [ TurboQuant Encoder ]
  - Precise float32      - PolarQuant + QJL Projection
  - Authoritative Truth  - Encoded to SQLite columns
                                │
                                ▼
                       [ SQLite Sidecar DB ]
                       - tq_indices, tq_norm, tq_qjl_sign
```

---

## 2. Mathematical Framework

TurboQuant compresses high-dimensional float32 vector spaces into compact, disk-friendly indices using two main operations: **Lloyd-Max Polar Quantization** and **Johnson-Lindenstrauss (JL) Residual Sign Projections**.

### A. Lloyd-Max Polar Quantization (PolarQuant)
High-dimensional visual and audio embeddings (e.g., CLIP's 768-d or DINOv2's 1024-d spaces) are first mapped from Cartesian coordinates $\vec{x}$ to Polar coordinates $(r, \vec{\theta})$.
1. **Norm Quantization**: The vector magnitude (L2 norm) $r = \|\vec{x}\|_2$ is quantized using a 1D Lloyd-Max quantizer. Lloyd-Max calculates optimal decision boundaries and centroids that minimize the mean squared quantization error (MSQE) for the empirical norm distribution of target embeddings:
   $$\min \sum_{i=1}^{K} \int_{t_i}^{t_{i+1}} (r - c_i)^2 p(r) \, dr$$
   Where $t_i$ represent the decision boundaries and $c_i$ represent the reconstruction centroids. This is compressed into a single `uint8` (`tq_norm`).
2. **Angular Quantization**: The direction vector $\vec{\theta} = \vec{x} / r$ is mapped to a set of discrete angular centroids using a pre-computed spherical grid codebook. The closest codebook index is stored in `tq_indices`.

### B. Johnson-Lindenstrauss (JL) Residual Projections
To capture the residual information lost during polar quantization, TurboQuant projects the quantization error vector (the residual $\vec{e} = \vec{x} - \hat{x}$) onto a random subspace:
1. We define a fixed, deterministic pseudo-random projection matrix $R \in \mathbb{R}^{m \times d}$ where $m \ll d$ (typically $m=64$ or $128$ projection dimensions).
2. The residual is projected to obtain a signature vector:
   $$\vec{s} = R \vec{e}$$
3. The signature is binarized using its sign, yielding a highly compact bit-array:
   $$\text{bits}_j = \begin{cases} 1 & \text{if } s_j \geq 0 \\ 0 & \text{if } s_j < 0 \end{cases}$$
4. These bits are stored as a blob/integer (`tq_qjl_sign`). First-stage distance approximations combine the codebook angular distance with a Hamming distance check on the residual sign bits, satisfying the Johnson-Lindenstrauss lemma for pairwise distance preservation.

## 3. First-Stage Query Pre-Filtering

During a search query:
1. The text or media query is embedded to a `float32` vector $\vec{q}$.
2. The SQLite engine performs a fast scan over the sidecar columns:
   - Approximate distances are calculated using the codebook index and the residual Hamming distance.
3. The top-$N$ (e.g., $N=100$) candidate scenes are pruned dynamically.
4. The authoritative high-precision `float32` vectors for these $N$ candidates are fetched from FAISS/Qdrant to compute exact cosine similarity and produce the final re-ranked result list.

This hybrid approach yields **$10\times$ faster query pre-filtering** while maintaining **$>99.8\%$ recall** compared to a raw flat scan of the full float32 index.

---

## 4. Cache Consistency & Invalidation

To ensure sidecar columns never drift from the authoritative Qdrant/FAISS index:
* **Write Path**: Every ingestion transaction updates the scene manifest in SQLite and Qdrant atomically. The write transaction computes the TurboQuant fields synchronously before committing the SQLite record.
* **Invalidation Trigger**: Any update to the perception model version or changes in the embedding dimension registry triggers an automatic invalidation of the sidecar columns.
* **On-Demand Re-hydration**: If the launcher detects that the SQLite database has missing or invalidated TurboQuant sidecar values while the authoritative Qdrant collection is populated, it boots a background worker to read the Qdrant index, re-quantize the vectors, and backfill SQLite. No user-created data is lost.
