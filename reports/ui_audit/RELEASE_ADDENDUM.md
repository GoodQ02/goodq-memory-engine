## 1. API Version Source Audit & Reconciliation (R1)
- **Codebase Declaration**: The canonical software version is declared in `goodq_version.py` as:

  This version is imported and exposed by the `/runtime/status` endpoint in `api/routes/runtime.py` and FastAPI application setup in `api/main.py`. It is also embedded in the NSIS installer files (`scripts/install/goodq4all_installer.nsi`) and metadata (`scripts/install/versioninfo.json`).
- **Release Tag**: The repository is tagged at `v2.5.4` on commit `63cca655865e5808ff5e76681c5dc926723c70aa` ("WSL2 Audio Gated Models & Model Provisioning Sprint").
- **Reconciliation & Analysis**: The codebase version string and repository release tags are conceptually identical and represent the same software release. The mismatch (reporting `2.5.3` while tagged `v2.5.4`) is a release process oversight where `goodq_version.py` was not bumped during the `v2.5.4` tagging commit. Bumping `goodq_version.py` and running the NSIS version sync scripts in future sprints will align them.

## 2. Scene Count Census & Reconciliation (R2)
- **Database Path**: `%DATA_ROOT%\GoodQ_Data\epochs\epoch_2026_06_21_family_clean_01\memory.db` (where %DATA_ROOT% is the data root folder).
- **Census Results**:
  An SQLite census script was run to inspect the `scenes` table in `memory.db` under the active epoch:
  - **Total Materialized Scene Records**: 282 rows
  - **Logical Index Records**: 141 rows (IDs like `scene_0000` to `scene_0140`, generated by `video_scene_detect`)
  - **Materialized/Signal Records**: 141 rows (IDs are 64-character SHA-256 hashes, generated by downstream perception/enrichment workers)
  - **Temporal Alignment**: All 141 logical index records align exactly 1-to-1 temporally (matching start and end times) with the 141 hashed signal records. No overlaps or duplicate physical scenes exist.
- **UI Timeline Rendering**:
  - The default UI timeline is driven by the temporal index specification in `temporal_index.json`, which defines exactly 141 segments keyed by SHA-256 hashes.
  - The timeline API `/api/videos/{video_id}/timeline` returns these 141 segments.
  - Therefore, the UI renders exactly 141 scene cards, and there are no duplicate user-visible scenes. The 282 rows in `scenes` represent two parallel references (logical sequence vs signal hash) to the same 141 physical scene intervals.
